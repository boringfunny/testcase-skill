# 旧图与变更

## 旧图转表

读取当前保存的XMind节点、完整备注、路径和原ID。无ID时分配稳定ID并说明。原图不覆盖，不用旧计划替代当前图。

能真实恢复v2字段时建v2；无法恢复则用旧结构加`--allow-legacy`。旧结构title、cases、questions，每例id/path/title/action/expected/impact/priority/kind/evidence/ideas/questions，original_notes保存完整备注。evidence引用本次当前图节点，不宣称已核对原始策划。

旧格式不生成v2覆盖/准备/变更模型，不报告覆盖率。原多场景限制写scope_notes。用户只要另出Excel时，可生成配套图用于一致性检查，但只交付所需Excel，保持原图不动。

## 设计变更

读取当前需求与上次`.support/design-baseline.json`，确认同一需求/版本关系。设计者维护稳定规则ID和用例ID，脚本不猜文字对应。

复核原文→规则→覆盖→用例，必要时修改步骤/预期。导出加`--baseline`，比较用例设计、关联规则/原文、覆盖模型及Q。规则变化即使用例字面未改也会标需重新验证；新增/移除单列。所有当前结果留空，未知规则可预设待确认。

基线只有设计指纹，不保存实测结果。未变化不自动复用历史通过；需要历史结果时另存历史表并核实证据适用性。指纹不证明语义等价，格式变化可能触发复核；未登记规则的变化可能漏掉，因此仍须全文变更审查。

`xmind_points`只影响导图展示，新增或改写简述不纳入设计指纹；旧V2基线仍可直接比较。改动真实步骤、预期、规则、覆盖模型或Q仍按原逻辑比较。旧V2计划省略简述时原详细分支保留并给出提示；旧图转换不自动生成简述，原节点文字与完整备注保真优先。

## 安装

2.3.0将Excel改为十列AI实现检查主表及检查详情；静态依据充分可通过。旧待实测进入兼容状态，禁止批量改为通过。设计计划无需增加字段，业务设计指纹不变；旧计划缺少简述时主表用标题，完整设计保留详情。旧回填表的逐条迁移边界见[验收约定](acceptance-contract.md)；导出器不自动转换历史结论。

安装使用 `scripts/install.py --skills-dir <父目录>`，完整复制当前技能目录，默认拒绝同名覆盖。V5安装身份与校验要求见下节；不更新任何已有版本目录。

## 独立V5 5.0.0

V5从V3 3.0.1独立发布，包根目录与调用名为game-requirement-test-docs-v5，四份模板、通用思路、样本与脚本全部自包含。新设计使用--require-v5同时检查展示字段和V3原有必填内容；旧schema_version=2计划省略此参数仍可导出，不自动归类、不重编号、不迁移历史回填。

旧计划不增加字段时设计指纹保持不变。新增检查项、改变检查目标或问题影响说明属于设计变化，关联用例需重新核对；展示排序不改变指纹。旧导图保真转换不重写原节点、原备注或推导新的服务端处理。

安装器拒绝同名覆盖。制作包时排除__pycache__及pyc，先验证ZIP与暂存目录相同、隔离安装和重复安装拒绝，再安装独立V5。原版、V2、V3、V4及用户历史成品保持原样。

3.0.1将Excel H列替换为最短验收路径，设计阶段从acceptance_path预填，检查结果仍留空。旧计划无路径可兼容导出并报告缺项，不能把历史H列的风险建议自动视为路径；原工作簿保留不迁移。短路径是阅读指引，不改变业务指纹；业务变化须修改详细设计字段。


## V5补充

V5 5.0.0独立安装，兼容schema_version=2；旧计划无展示配置时保持原组织。template_profile、template_decisions、display_group、display_path是展示信息，不参与业务指纹；新增review_focus及实际设计变更仍参与指纹。原path和ID不迁移，历史回填不自动转换。
