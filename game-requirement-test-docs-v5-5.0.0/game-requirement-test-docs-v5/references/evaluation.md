# 设计质量评测

工具自测与真实需求评测分开。self_test.py用合成资料验证提取、引用拒绝、双格式一致、反馈公式、设计计数、变更传播及覆盖保护，不能证明真实需求漏测率下降。

用户要求评测或已有真实输出可复核时，选授权使用且经人工审查的需求，涵盖简单交互、多条件资格、状态流转、金额/时间边界、规则冲突和一次变更。数量按资料与成本决定，不编造真实需求。

先登记人工审查关键规则与缺口；同一需求版本、资料、模型设置和时间限制比较版本。尽量隐藏版本标签再评分，保存输出与评分依据。

| 指标 | 口径 |
|---|---|
| 关键规则遗漏 | 已审查规则中缺有效测试覆盖的清单；分母只限本轮已审查规则 |
| 无依据预期 | 硬性预期无原文/获批规则支持且未待确认；推导与建议单审 |
| 重复用例 | 前置、操作、判定实质相同且无不同风险理由 |
| 执行者追问 | 为确定数据、准备、操作或判定仍需追问的用例 |
| 修订成本 | 实际人工审查修改时间，不用生成速度替代 |
| 历史缺陷覆盖 | 仅读设计只能说可覆盖/待验证；运行后才能声称检出 |
| 变更定位 | 受影响用例漏标、误标与ID稳定情况 |

未测指标写未测；没有对照数据不宣称v2更准确或提高百分之多少。需执行的检出效果交给另行授权的验收流程，本技能只记录交接与未测范围。

## 服务端设计回归

服务端设计部分沿用V3，保留原回归样例与思路引用。重点检查：是否把资格、配置、分支、状态与资产结果说清楚；客户端是否简洁且保留独立判定；待确认问题是否可回答且解释影响。样例是人工设计的表达对照，不能证明模型在真实需求上自动提升质量。

测试review_focus与impact的非法输入、严格模式拒绝缺填、旧计划兼容、排序与ID跳转、检查项/影响变更触发复核、只改短句不影响指纹。保留状态组合、两文件一致性、源保护及安装回归；原生兼容性单独记录。

V5维护时运行self_test.py覆盖分类排序、展示字段指纹排除、严格字段检查和旧计划回退。用同一业务计划对比V3/V5；另验证活动、养成、英雄和纯客户端结构。辅助预览不代表XMind原生兼容，原生打开与Excel重算单独记录。
