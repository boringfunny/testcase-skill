# V5 通用模板展示

四份用户模板快照位于`assets/format-templates/`，manifest.json记录文件名、SHA-256及完整提取标题树。安装后只读随包快照，不引用原桌面位置。原通用游戏测试思路仍按“用户指定 → 工作区可用 → 随包快照”选择，模板不能代替设计方法或业务证据。

按需求类型选择活动、玩法、养成、英雄；无法归类用通用共同框架。玩法模板中心标题误写活动，输出必须用本次需求名称。英雄模板只有占位结构与标签说明，不能从中补造英雄规则，也不复制已验收、未通过等标签。

显示顺序：入口 → 红点 → 具体主功能名称（可多个，按首次出现）→ 特殊点验证 → 异常状态 → 配置检查 → UI检查。只生成存在实际用例的分支；不为凑模板分类复制同一用例。主功能、次级模块、功能点等占位名称替换为有业务意义的名称，下级分组只有确有阅读价值时保留。

服务端条件、状态、数据校验放对应业务分类；独立配置、异常、关联场景按各自主要目标归类。纯显示、布局、动画统一放UI检查并按业务分组，保留需独立判定的结果；资格、金额、奖励、时间等服务端数据仍单独设计。是否归入入口取决于实际检查目标，不能把所有资格限制都机械归入入口。

模板里的0点、邮件补发、分辨率、关联系统只属于候选方向。需求未给时间、补发或关联规则时不默认其存在；确实影响需求判断的缺口登记通俗Q，缺材料和缺环境不写需求Q。用template_decisions说明分类适用性，写入.support/validation.json，不增加主文档长说明。

末端固定为测试点 → 人工简述；完整前置、数据、步骤、检查项、预期及证据放备注和Excel详情。保留待确认规则和依据与使用说明页，不恢复条件/操作/判定等固定子分支。

样式采用浅暖背景#eee8e6、棕色主节点#c1aba5、浅色子节点#e6ddda、线条#88675e、深色文字#2d221f，微软雅黑、圆角、曲线连接。左右展开：前ceil(分类数/2)类在右，其余在左；一级分类下的深层分组默认折叠。JSON与classic XML均写入相应样式；具体应用是否按这些样式渲染须另作原生验证。

Excel保持七页十列和原输入区，分类不生成额外标题行。主表模块使用展示路径首项，顺序与导图路径树一致，详情记录完整路径。修改展示不改业务指纹；新V5严格检查见计划契约，旧计划不猜分类，旧导图保真转换不套新格式。
